## 2026-11-12 规划器改为逐段独立推荐车门（Issue #3）

- 按 2026-11-10 确认的换乘模型改写 `src/core/planner.ts`：每段推荐车门只由该段终点（换乘站或目的站）的设施按模式最优决定，各段互相独立；换乘路径改为「下车门 → 下一程站台」，起点路径为「付费站厅 → 首段站台」，目的站路径为「下车门 → 付费站厅」。
- 站台没有独立节点，用其全部车门节点代表，取到达最近的一个；路径说明末尾改写为「到站台」，不再指向候车门，也不再出现「前往X号车厢Y号门候车」。这是对「站台」的近似，没有改 Schema。
- 并列最优的车门全部输出，`DoorRecommendation` 新增可选 `arrivalPath`；完整性标记改为按段判断。
- 移除 `JourneyRoute.doorCombinations` 与 `DoorCombination`；页面去掉「整程搭配」弹窗、组合选择状态和「到X号车厢Y号门」候车提示。
- 线网数据、发布包和本机个人副本格式不变，无需迁移；路线排序所用的步行米数口径变了（不再含站台上走到下一程上车门的距离）。
- 验证（Node 18，LF 检出）：`typecheck`、`data:validate`（真实与演示）、`network:check`、`fare:check`、H5 与微信小程序构建通过；`npm test` 304 通过、14 跳过（SQLite）。微信开发者工具与真机未验收。

## 2026-11-12 修复换行符与测试超时

- 新增 `.gitattributes`：文本文件固定 LF，图片、xlsx 等标为二进制。本机系统 Git 的 `core.autocrlf=true` 曾把新检出的票价数据转成 CRLF，使票价测试的哈希校验失败。已有提交内容重新规范化后无变化；默认 autocrlf 的临时检出中 CRLF 文件为 0，票价测试通过。
- 测试超时：分段计时显示，最慢的几个集成用例要在真实线网上连续做多次完整规划（每次约 0.5 秒），单独运行 4–6 秒，全量并发时越过默认 5 秒。试过预先导入会话模块，只省 1–2 秒，已放弃；改为在 `vitest.config.ts` 把单个用例超时放宽到 20 秒。连续三次全量运行均为 303 通过、0 失败、14 跳过，最慢用例 5.6–7.0 秒。
